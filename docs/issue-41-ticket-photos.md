# 任务26（Issue #41）工单现场照片

依据软件需求规格说明书 V1.0 §3.10、FR-FILE-001～002、AC-P1-01 和数据保留要求。2026-11-28 经需求提出者确认以下补充规则。

## 已确认规则

- 报修人创建工单时可选上传；创建后报修人和当前维修人员可在非终态追加。取消申请待审不冻结照片追加，管理员只查看。
- 已完成、已取消、不予受理禁止追加。普通用户不提供替换或删除，原始报修信息不因照片追加被覆盖。
- 每工单总共最多5张，每张最多5MiB，仅接受扩展名与实际内容匹配的 JPG/JPEG/PNG。验证完整解码、限制像素并重编码，去掉 EXIF/位置等元数据及附加内容。
- 关闭时间取当前终态对应的真实状态变更或取消历史，保留至关闭时间满12个日历月；闰年2月29日顺延年对应2月28日。缺少可信关闭记录时禁止清理。
- 不自动清理。期满后仍须业务管理员提供政策依据、原因并显式执行处置；保留照片元数据、工单历史、处置人、时间和成功/失败记录。

## 页面与存储

- 创建页 `/tickets/create/` 支持多选照片，与工单及初始历史同事务创建。
- 详情页展示照片、上传人和时间，提供追加表单。上传接口为 `POST /tickets/<pk>/photos/`，只接受照片文件，执行 CSRF 和服务端权限校验。
- 文件保存在 `PRIVATE_DOCUMENT_ROOT/ticket_photos/`，使用随机存储名，不进入公开 `MEDIA_ROOT`。
- `GET /tickets/photos/<photo_id>/` 每次根据最新账号、工单提交人及当前处理人重新鉴权，记录访问人和时间，返回 `private, no-store` 与 `nosniff`，不提供文件系统直链。转派后旧维修人员即失去读取和上传权限。
- 与工单操作共用写锁，锁内统计数量，保证并发追加不超过5张。数据库或文件保存失败时回滚数据库并清理本次已写文件，包括磁盘部分写入失败。创建、上传及清理意图使用 durable 事务，要求服务拥有最外层业务事务，拒绝外层事务回滚留下文件或抹去清理审计的调用方式。

## 升级、备份与清理

执行 `python manage.py migrate`，新增 `tickets/0005`。原有账号、工单和附件保留。

`backup_site` 自动覆盖私有照片目录；备份校验还核对数据库内未处置照片的文件存在性、大小和 SHA-256，照片缺失时拒绝产生有效备份。`restore_site` 继续只恢复到独立新目录，部署恢复环境时将数据库和 `PRIVATE_DOCUMENT_ROOT` 指向恢复副本。旧版无照片表的备份仍可校验，恢复后执行迁移。

按正式资料政策审批后，维护人员可执行以下命令，`--actor` 必须对应启用且审核通过的业务管理员。

```powershell
python manage.py dispose_ticket_photos --ticket <工单ID> --actor <管理员ID> --reason "批准的清理原因" --policy "政策文件或审批编号" --confirm
```

清理意图先持久化，再处理文件；失败保留审计。存在未完成清理意图时禁止重复批处理，应先由维护人员核查文件与记录。照片审计不随运行日志轮转删除，备份保留和业务照片最低保留期分别执行。
