# Issue #21：工单查询、历史展示与追加说明

## 功能

- 沿用各角色的工单可见范围：报修人查看本人提交的工单，
  维修人员查看当前分派的工单，管理员查看全部。
- 支持按关键词、状态、优先级和取消待审标记组合筛选。
- 关键词支持工单编号、标题、楼栋快照及具体位置。
- 详情按时间和记录ID顺序展示历史，包括记录人、时间、
  事件类型和说明内容；列表及详情同时展示主状态和取消待审标记。
- 追加说明使用已有 TicketHistory 的 note_added 类型，
  不覆盖原始报修信息、旧历史或工单状态。
- 提交接口仅接受说明正文；记录人由当前登录会话决定。
- 服务层重新读取账号、当前处理人及状态，并在事务内追加。
- 保存失败回滚；SQLite 锁冲突进行有限重试并提供失败提示。

## 当前追加范围（待组长确认）

- 报修人、当前分派的维修人员及管理员可以在非终态工单追加。
- 取消待审期间仍允许有权限的人查看和追加说明。
- 不予受理、已完成、已取消工单只读。
- 说明不能代替维修结果、完成确认或取消审核。
- 终态和各角色追加范围确认后，再作为最终验收规则。

## 接口

POST /tickets/<工单ID>/notes/

字段：text，去除首尾空白后必填，最多2000字。
需要登录及CSRF校验；不接受记录人、工单状态等额外字段。
